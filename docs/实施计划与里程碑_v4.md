## 关键原则总结

### ✅ 我们要做的：
1. **只增不改** - 新功能放新文件新目录
2. **最小改动** - 只加必要的几行代码
3. **每周有成果** - 每周都能看到进展
4. **随时可回退** - 改坏了就回，不影响大局

### ❌ 我们不做的：
1. **不重构现有目录** - 旧代码能用就行
2. **不为了完美反复改** - 够用就行
3. **不一次性搞完** - 分批上线，风险可控
4. **不破坏现有功能** - 原有功能始终能正常用
