## 🚨 当前存在的问题（2026-06-20 诊断）

### 问题 1：编辑模式下拖拽功能异常或不工作 ✅ 已修复（2026-06-20）

**严重程度：🔴 高（核心功能）** → **已修复**

**现象描述：**
- 用户进入编辑模式后，尝试拖拽图表卡片移动位置，可能无反应或行为异常
- 从截图观察：图表显示正常，但无法自由移动

**根因分析：**

```
┌─────────────────────────────────────────────────────────────┐
│ DashboardItem.tsx 结构分析                                   │
│                                                             │
│ <div style={{ ...styles.item, ...gridStyle }}>  ← 外层容器 │
│   onMouseDown={handleDragStart}        ← 拖拽事件绑定      │
│   onClick={() => setSelectedChartId()}  ← 点击事件绑定      │
│                                                             │
│   {savedChart ? (                                          │
│     <>                                                     │
│       {title && <div>标题</div>}                            │
│       {loading/error/chartConfig ? (                        │
│         <DashboardItemContent ... />  ← ECharts 渲染区域    │
│         ↑ 这个组件也有 gridStyle！                           │
│       )}                                                    │
│                                                             │
│       {/* 缩放手柄 */}                                      │
│       <div style={styles.resizeHandleRight} />              │
│       <div style={styles.resizeHandleBottom} />             │
│       <div style={styles.resizeHandleCorner} />             │
│     </>                                                     │
│   )}                                                        │
│ </div>                                                      │
└─────────────────────────────────────────────────────────────┘
```

**具体问题点：**

| 子问题 | 位置 | 描述 | 影响 |
|--------|------|------|------|
| **1a. gridStyle 重复设置** | DashboardItemContent:157-161 行 vs DashboardItem:400-416 行 | 子组件 DashboardItemContent 也设置了 `gridColumn`/`gridRow`，与父组件重复 | 可能导致 CSS Grid 计算异常 |
| **1b. 事件冲突** | 外层 div onMouseDown vs 内部 ECharts | 点击图表区域时，ECharts 先捕获鼠标事件（tooltip/缩放），阻止冒泡到外层拖拽处理器 | 在图表区域无法开始拖拽 |
| **1c. onClick 与拖拽竞争** | 同一元素上的 onClick 和 onMouseDown | 快速点击时两者都触发；慢速拖拽时 onClick 也会触发（选中图表而非移动） | 操作体验混乱 |

**建议修复方向：**
- 移除 DashboardItemContent 中的 gridStyle（它不应该参与 Grid 布局）
- 将拖拽手柄移到独立的拖拽区域（如图表标题栏或专门的 drag handle），避免与 ECharts 冲突
- 增加"拖拽延迟"判断：mouseDown → mouseUp 时间差 < 200ms 视为 click，否则视为 drag start

### 问题 2：缩放手柄不可见或难以操作 ✅ 已修复（2026-06-20）

**严重程度：🟡 中（影响易用性）** → **已修复**

**现象描述：**
- 编辑模式下只能看到右下角的圆形缩放手柄（corner）
- 右侧和底部的边框手柄完全看不到

**根因分析：**

```typescript
// DashboardItem.tsx 当前样式定义
const styles = {
  resizeHandleRight: {
    position: 'absolute',
    right: '-4px', top: '8px', bottom: '8px',
    width: '8px',
    cursor: 'ew-resize',
    background: 'transparent',  // ❌ 完全透明！
    zIndex: 30,
  },
  resizeHandleBottom: {
    position: 'absolute',
    bottom: '-4px', left: '8px', right: '8px',
    height: '8px',
    cursor: 'ns-resize',
    background: 'transparent',  // ❌ 完全透明！
    zIndex: 30,
  },
  resizeHandleCorner: {          // ✅ 唯一可见的手柄
    position: 'absolute',
    right: '-8px', bottom: '-8px',
    width: '16px', height: '16px',
    background: 'var(--primary)',  // 可见的蓝色圆点
    borderRadius: '50%',
    cursor: 'nwse-resize',
    zIndex: 40,
  },
};
```

**问题：** 右侧和底部手柄 `background: 'transparent'` 且只有 8px 宽/高，用户根本看不到也点不到。
只有 corner 手柄（16px 蓝色圆点）可用。

**建议修复方向：**
- 给右侧/底部手柄添加 hover 时的高亮效果（如 2px 彩色边框）
- 或增大热区尺寸（如 12-16px），hover 时显示视觉反馈
- 参考 Figma/Miro 等工具的缩放手柄设计

### 问题 4：布局保存机制脆弱 ✅ 部分修复（2026-06-20）

**严重程度：🟠 中高（可能导致数据丢失）** → **部分修复（并行+错误收集已完成，批量接口待后端支持）**

**当前保存流程（DashboardPage.tsx handleToggleEdit）：**
```typescript
// 退出编辑模式时：
1. setSavingLayout(true);           // 显示"保存中..."
2. for (const [itemId, layout] of Object.entries(tempLayout)) {
     await updateDashboardItem(itemId, layout);  // 逐个 API 调用！
   }
3. setIsEditing(false);             // 退出编辑模式
```

**潜在风险：**
- **性能风险**：N 个图表项 = N 次 `updateDashboardItem` API 调用，串行执行
- **中断风险**：如果第 3 个 API 失败，前 2 个已保存但后 N-3 个未保存 → 数据不一致
- **无事务保护**：没有批量更新接口，每个 item 独立提交
- **无错误恢复**：失败后没有 rollback 机制

**建议优化方向：**
- 后端新增 `batch_update_dashboard_items(dashboard_id, items[])` 批量接口
- 或前端改为并行调用 `Promise.all()` + 收集失败项重试
- 保存前做 diff 对比，只更新真正变化的项

3. filterValues 变化时触发 DashboardItem 重新渲染
