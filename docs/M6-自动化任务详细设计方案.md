## 二、新增系统表（2 张，均为 `__` 双下划线前缀，符合系统表规范）

### 表 1：`__automation_tasks`（任务定义表，约 25 列）

```sql
CREATE TABLE IF NOT EXISTS __automation_tasks (
    id TEXT PRIMARY KEY DEFAULT (lower(hex(randomblob(16)))),
    name TEXT NOT NULL,                                          -- 任务显示名称
    description TEXT DEFAULT '',                                 -- 备注
    task_type TEXT NOT NULL DEFAULT 'sql',                       -- sql | refresh_chart | refresh_dashboard | export_csv
    payload TEXT NOT NULL DEFAULT '{}',                          -- JSON 串
    schedule_mode TEXT NOT NULL DEFAULT 'interval',              -- interval | cron | manual
    schedule_value TEXT NOT NULL DEFAULT '3600',                 -- interval=秒数; cron=形如"0 */1 * * *"; manual=空
    timezone TEXT NOT NULL DEFAULT 'local',                      -- 时区标签，默认本机时间
    state TEXT NOT NULL DEFAULT 'enabled',                       -- enabled | disabled | paused
    project_id TEXT DEFAULT '',                                   -- 归属项目 / 数据库；空=全局
    next_run_at INTEGER,                                          -- 下次运行 unix 时间戳（秒）
    last_run_at INTEGER,                                          -- 最近一次运行
    last_run_status TEXT,                                         -- success | failed | running | skipped
    last_run_duration_ms INTEGER,                                 -- 上次执行耗时
    total_runs INTEGER NOT NULL DEFAULT 0,                       -- 累计运行次数
    success_runs INTEGER NOT NULL DEFAULT 0,
    failed_runs INTEGER NOT NULL DEFAULT 0,
    retry_on_fail INTEGER NOT NULL DEFAULT 0,                    -- 失败自动重试次数（0=不重试）
    retry_interval_secs INTEGER NOT NULL DEFAULT 60,             -- 重试间隔
    timeout_secs INTEGER NOT NULL DEFAULT 300,                   -- 单次执行超时
    notify_on_success INTEGER NOT NULL DEFAULT 0,                -- 成功时 Toast 通知
    notify_on_failure INTEGER NOT NULL DEFAULT 1,                -- 失败时 Toast 通知
    tags TEXT NOT NULL DEFAULT '[]',                              -- JSON 字符串数组，分类用
    created_by TEXT NOT NULL DEFAULT '',
    created_at INTEGER NOT NULL DEFAULT (strftime('%s','now')),
    updated_at INTEGER NOT NULL DEFAULT (strftime('%s','now'))
);

CREATE INDEX IF NOT EXISTS idx_automation_tasks_next_state ON __automation_tasks(next_run_at, state);
CREATE INDEX IF NOT EXISTS idx_automation_tasks_type ON __automation_tasks(task_type);
CREATE INDEX IF NOT EXISTS idx_automation_tasks_project ON __automation_tasks(project_id);
```

**payload schema（按 `task_type` 区分）**：

| `task_type` | payload JSON | 说明 |
|---|---|---|
| `sql` | `{ sql: string, outputMode: 'history_only' }` | 复用 `commands/sql.rs::split_sql_statements` → `execute_sql` |
| `refresh_chart` | `{ chartId: string }` | 调用 `DashboardService::get_saved_chart(id)` → 执行 `saved_chart.sql` → 重新生成 `config` |
| `refresh_dashboard` | `{ dashboardId: string }` | 读取 `Dashboard.items` 中全部 `chart_id` → 循环或并行 refresh_chart |
| `export_csv` | `{ sql: string, outputPath: string, delimiter: ',', withHeader: true }` | 执行 SQL → 以 CSV 写入磁盘 |

### 表 2：`__automation_runs`（运行日志表，append-only，不可变）

```sql
CREATE TABLE IF NOT EXISTS __automation_runs (
    id TEXT PRIMARY KEY DEFAULT (lower(hex(randomblob(16)))),
    task_id TEXT NOT NULL,                                        -- 外键 __automation_tasks.id
    status TEXT NOT NULL DEFAULT 'running',                       -- running | success | failed | skipped
    started_at INTEGER NOT NULL DEFAULT (strftime('%s','now')),
    finished_at INTEGER,
    duration_ms INTEGER,
    affected_rows INTEGER,
    output TEXT,                                                  -- 简短输出 / 失败时的错误信息（最大 4KB）
    retry_count INTEGER NOT NULL DEFAULT 0,                      -- 本次是第几次重试（0 为首次）
    trigger_type TEXT NOT NULL DEFAULT 'schedule',               -- manual | schedule
    created_at INTEGER NOT NULL DEFAULT (strftime('%s','now'))
);

CREATE INDEX IF NOT EXISTS idx_automation_runs_task_created ON __automation_runs(task_id, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_automation_runs_status ON __automation_runs(status);
```

## 三、任务全生命周期状态机

```
                ┌──────────────┐
                │   created    │   ← 前端 create_task，初始 state='enabled'
                └──────┬───────┘   （若 schedule_mode='manual'，next_run_at=NULL）
                       │
                       ▼
                ┌──────────────────────┐
  ┌─ schedule:  │     enabled/running  │  ← ScheduleEngine 每 30s 扫描
  │ tick:       │（正在执行时标记为     │    命中条件：state='enabled' AND next_run_at ≤ now
  │ 标记临时     │  running，避免并发)  │    AND last_run_status != 'running'
  │ running      └──────────┬───────────┘
  │ 执行                    │ 执行完成
  │                         │ ┌──────────────┐
  │                         │ │ success → 更新│
  │                         │ │ total/success │
  │                         │ └──────┬───────┘
  │                         │        │（正常结束）
  │                         ▼        ▼
  │                    ┌──────────────────┐
  │                    │  enabled/idle    │ ← 正常情况下：重新计算 next_run_at = now + interval
  │                    └─────────┬────────┘   （或 CronExpr.next_after(now)）
  │                              │
  │ 失败（失败策略）              │ 手动操作
  │ 若 retry_count < retry_on_fail│
  │  └→ next_run_at = now + retry_interval_secs
  │                               │ 调用 enable_task / disable_task
  │ 若超过重试次数                    或前端"禁用"按钮
  │  └→ state='disabled'              │
  │                                   ▼
  │                              ┌────────────────┐
  │                              │    disabled    │ ← ScheduleEngine 忽略
  │                              └────────┬───────┘
  │                                       │ 调用 enable_task
  │                                       ▼
  │                              ┌────────────────┐
  │                              │     paused     │ ←（可选）仅手动触发时执行
  │                              └────────┬───────┘
  │                                       │ 调用 delete_task
  │                                       ▼
  │                              ┌────────────────┐
  │                              │     deleted    │ ← 删除任务 + 级联删除最近 runs
  │                              └─────────────────┘
  │
  └────────────────────────────────────────────────────────────────────┘
```

## 四、ScheduleEngine 设计（进程内调度器）

**设计目标**：
- 应用启动时自动启动；应用关闭时优雅退出
- 每 30 秒做一次 tick 扫描
- 全局并发上限：最多同时运行 3 个任务
- 任务失败并超过重试次数 → 自动 `state='disabled'`

**关键实现要点（伪代码）**：

```rust
pub struct ScheduleEngine;

impl ScheduleEngine {
    pub fn run_forever(db_manager: Arc<DatabaseManager>, shutdown: Arc<AtomicBool>) {
        std::thread::spawn(move || {
            loop {
                if shutdown.load(Ordering::Relaxed) { return; }
                std::thread::sleep(Duration::from_secs(30));

                let conn = match db_manager.get_connection() { Ok(c)=>c, Err(_)=> continue };

                // 读取全局开关：settings.category='automation' AND key='taskEngineEnabled'
                // 若为 'false'，跳过本次 tick

                // 1. 扫描满足条件的任务
                //    SELECT id FROM __automation_tasks
                //      WHERE state='enabled' AND next_run_at IS NOT NULL
                //        AND next_run_at <= strftime('%s','now')
                //        AND last_run_status != 'running'
                //      ORDER BY next_run_at ASC LIMIT 3

                // 2. 依次执行（串行，200ms 间隔）
                //    for id in ids { TaskService::execute(&conn, &id, "schedule"); }
            }
        });
    }
}
```

**Cron 解析要点**：
- 标准 5 字段：`分 时 日 月 周`
- 语法支持：`*`、`N`、`N-M`、`*/N`、`N,M,...`
- 从当前时间开始以分钟步进查找第一个符合条件的时间点

## 七、数据链路梳理（端到端，4 类任务）

**链路 1：`task_type='sql'`**
- 前端创建 → taskStore → Rust create_task → INSERT __automation_tasks
- ScheduleEngine tick → execute(...) → 读取 payload.sql → 调用 execute_sql 底层 → 写入 __query_history
- 更新 __automation_runs + __automation_tasks.next_run_at

**链路 2：`task_type='refresh_chart'`**
- ScheduleEngine tick → execute(...) → 读取 payload.chartId → get_saved_chart(chartId) → 执行 saved_chart.sql
- 重新生成 echarts config JSON → update_saved_chart(...) → UPDATE __saved_charts
- 写入 __automation_runs

**链路 3：`task_type='refresh_dashboard'`**
- 读取 payload.dashboardId → get_dashboard(id) → 遍历 layout 中所有 chartId
- 对每个 chartId 完整执行链路 2
- 写入 __automation_runs affected_rows=成功刷新的图表数

**链路 4：`task_type='export_csv'`**
- 读取 payload.{sql, outputPath, delimiter, withHeader} → 执行 SQL → 以 CSV 写入磁盘
- 写入 __automation_runs

### 9.2 目前能做的工作

1. **定时 SQL 执行任务**
   - 在 SQL 查询页点击 "⚡ 定时执行" 立即创建任务（预填当前 SQL）
   - 在任务中心手动创建任意 SQL 任务
   - 支持 `interval`（秒级循环）、`cron`（5字段表达式，如 `0 9 * * 1-5`）、`manual`（仅手动触发）三种模式
   - 完整生命周期：启用/禁用、立即运行、编辑、删除、查看运行日志

2. **图表定时刷新任务（第二轮核心改进）**
   - **真执行 SQL**：`refresh_chart` 任务会执行该图表的 SQL，将结果 JSON 写回 `__saved_charts.last_result`，并更新 `last_run_at` 和 `updated_at`
   - 3 个快捷入口：图表库卡片、仪表盘工具栏、图表编辑边栏（第二轮新增）
   - 前端可读取 `lastResult` 跳过重复查询，大幅降低刷新仪表盘的开销

3. **仪表盘批量刷新任务**
   - 从仪表盘工具栏 "⚡ 定时刷新" 创建任务
   - 自动遍历 `__dashboard_items` 找到所有引用图表 ID，逐个调用 `refresh_saved_chart` 刷新
   - 单图表失败不影响其他图表（错误隔离）
   - 运行日志记录本次刷新了多少张图表、合计读取了多少行数据

4. **定时导出 CSV**
   - 创建任务时填入 SQL 查询语句和输出文件绝对路径 `outputPath`
   - 执行时运行查询 → 生成带表头的 CSV（逗号分隔，字段含逗号/双引号/换行符时自动转义）→ 写入指定路径
   - 未提供 `outputPath` 时仅在日志中报告行数

5. **任务中心主页与日志**
   - 3 项统计卡片 + 关键字/状态/类型筛选
   - 右侧详情抽屉显示任务配置 + 运行日志表格（时间、状态、耗时、触发类型、输出详情）

6. **Settings 调度引擎配置（第二轮生效）**
   - 引擎开关（`engineEnabled`）：调度引擎每次循环时读取，关闭后不再扫描/执行任务
   - 扫描间隔（`scheduleIntervalSecs`）：动态控制调度循环频率（10-3600 秒，默认 30）
   - 日志保留天数（`logRetentionDays`）：自动清理超期运行日志
   - 其他 4 项：默认失败重试次数、默认超时、失败通知、最大并发

### 10.3 图表缓存渲染策略详解

`DashboardItem.tsx` 中 chartConfig 生成的策略顺序（第三轮新增 **策略 0**）：

```
策略 0（优先）：筛选器未激活 && savedChart.lastResult 有 columns/rows → 直接调用 generateChartConfig
        ↓ 无缓存或筛选器激活
策略 1：savedChart.sql 为空 && savedChart.chartType='text' → 回退到静态 text 渲染
        ↓ sql 存在但执行失败
策略 2：执行 savedChart.sql → 调用 generateChartConfig
```

控制台日志示例：

```
[DashboardItem] 策略 0：使用自动化任务缓存（刷新时间: 2025/2/17 14:30:00）跳过 SQL 查询
```

**优势**：自动化任务定期刷新 `last_result` 后，前端渲染可直接消费，**避免重复执行相同 SQL**。用户打开仪表盘时的首屏渲染时间显著降低。

### 10.4 Cron 可视化编辑器设计

原输入：
```
[ 0 9 * * 1-5 ] ← 纯文本，需理解 cron 语法
```

第三轮改为：
```
┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐
│  0 │ │  9 │ │  * │ │  * │ │1-5 │   ← 分 / 时 / 日 / 月 / 周
└────┘ └────┘ └────┘ └────┘ └────┘
完整表达式：0 9 * * 1-5
```

用户输入任意一个字段时自动拼接为完整 cron 表达式。支持常见预设值：`*`（每）、`0 */1`（每小时整点）、`0 9 * * 1-5`（工作日早 9 点）等。

## 十一、技术风险与权衡

| 风险 | 影响 | 缓解策略 |
|---|---|---|
| **应用关闭时任务不运行** | 用户期望"离线也要跑" | UI 显式提示；作为桌面应用的明确限制 |
| **任务执行阻塞 UI** | 长 SQL 查询拖慢前端体验 | ScheduleEngine 在独立线程运行；前端不阻塞，只轮询状态 |
| **并发锁冲突** | 同一任务被多次启动 | 通过 `last_run_status != 'running'` 双重检查 |
| **SQL 任务破坏性** | 执行 DROP/DELETE 数据丢失 | 任务创建时关键字检测；admin 模式提示 |
| **运行日志无限增长** | 高频率任务撑大数据库 | `runsRetentionCount` 设置；每次运行前清理超过阈值的最旧 runs |
| **图表任务失败** | `saved_chart.sql` 不存在或图表已被删除 | 失败时写入清晰错误信息（"图表已被删除"）；任务自动 disabled |
