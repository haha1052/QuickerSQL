## 1. 双引擎架构

### 1.1 架构概览

```
┌─────────────────────────────────────────────────────────────────┐
│                      双引擎数据库架构                              │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│                          应用层                                   │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │                   前端界面                               │   │
│  └─────────────────────────────────────────────────────────┘   │
│                              │                                   │
│                              ▼                                   │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │                   Tauri 命令层                           │   │
│  └─────────────────────────────────────────────────────────┘   │
│                              │                                   │
│        ┌─────────────────────┼─────────────────────┐          │
│        ▼                     ▼                     ▼          │
│  ┌───────────┐       ┌───────────────┐     ┌───────────┐    │
│  │ 查询服务   │       │  导入服务      │     │ 仪表盘服务 │    │
│  └─────┬─────┘       └───────┬───────┘     └─────┬─────┘    │
│        │                     │                   │            │
│        └─────────────────────┼───────────────────┘            │
│                              ▼                               │
├─────────────────────────────────────────────────────────────────┤
│                          数据访问层                               │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │                  查询路由器 (VIEW 机制)                  │   │
│  └─────────────────────────────────────────────────────────┘   │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │    SQLite (事务型数据库)          │   DuckDB (分析型数据库)│   │
│  │                              │                          │   │
│  │  - 元数据存储                 │   - VIEW 映射           │   │
│  │  - 查询历史记录               │   - 查询缓存           │   │
│  │  - 仪表盘配置                 │   - 高性能分析查询     │   │
│  │  - 用户配置                   │   - 无需字符串替换     │   │
│  │                              │                          │   │
│  │  写入路径:                    │   读取路径:            │   │
│  │    数据导入 → SQLite →        │    用户 SQL → DuckDB   │   │
│  │      自动同步 VIEW            │      (通过 VIEW)       │   │
│  │                              │                          │   │
│  └─────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────┘
```

### 1.2 职责划分

| 引擎 | 用途 | 典型操作 | 特点 |
|------|------|---------|------|
| **SQLite** | 事务型操作 | 数据写入、元数据管理、配置存储 | ACID 保证、零配置 |
| **DuckDB** | 分析型查询 | 数据读取、聚合计算、复杂查询 | 列式存储、向量化执行、高性能 |

## 2. SQLite 元数据表设计

### 2.1 工作区目录结构

```
[工作区路径]/
├── quickersql.sqlite         # SQLite 元数据库
├── data/                  # 用户数据表（可选，也可以在 SQLite 中）
│   └── [表名].parquet     # 可选：使用 Parquet 格式
├── cache/                 # 查询缓存
│   └── [hash].cache       # 缓存文件
├── dashboards/            # 仪表盘配置
│   └── [id].json          # 仪表盘配置
└── exports/               # 导出文件
    └── [name].[ext]       # 导出的文件
```

### 2.2 核心元数据表

#### 2.2.1 查询历史表 (query_history)

```sql
CREATE TABLE IF NOT EXISTS query_history (
    id TEXT PRIMARY KEY DEFAULT (lower(hex(randomblob(16)))),
    
    -- SQL 内容
    sql TEXT NOT NULL,
    
    -- 执行信息
    executed_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    execution_time_ms INTEGER,
    row_count INTEGER,
    
    -- 状态
    success BOOLEAN DEFAULT TRUE,
    error_message TEXT,
    
    -- 分类和标记
    is_favorite BOOLEAN DEFAULT FALSE,
    tags TEXT, -- JSON 数组格式
    notes TEXT,
    
    -- 索引
    INDEX idx_executed_at (executed_at),
    INDEX idx_is_favorite (is_favorite)
);
```

**说明：**
- 存储所有执行过的 SQL 查询
- 支持收藏和标签功能
- 记录执行时间和结果大小
- 用于快速复用历史查询

#### 2.2.2 数据表元信息表 (tables)

```sql
CREATE TABLE IF NOT EXISTS tables (
    id TEXT PRIMARY KEY DEFAULT (lower(hex(randomblob(16)))),

    -- 表基本信息
    name TEXT NOT NULL UNIQUE,
    original_name TEXT,
    display_name TEXT,
    description TEXT,

    -- 状态：active | trashed
    status TEXT NOT NULL DEFAULT 'active',

    -- 回收站信息
    trashed_at DATETIME,
    trash_expires_at DATETIME,
    trash_file_path TEXT,

    -- 文件信息
    source_file_path TEXT,
    source_file_type TEXT, -- CSV/EXCEL/JSON/PARQUET
    source_file_size_bytes INTEGER,

    -- 统计信息
    row_count INTEGER DEFAULT 0,
    column_count INTEGER DEFAULT 0,

    -- 列结构（JSON）
    schema_json TEXT NOT NULL,

    -- 时间戳
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,

    -- 索引
    INDEX idx_name (name),
    INDEX idx_status (status),
    INDEX idx_created_at (created_at),
    INDEX idx_trashed_at (trashed_at)
);
```

**说明：**
- 记录所有用户数据表的元信息
- 存储表结构（schema_json）用于快速预览
- 记录来源文件信息

#### 2.2.3 查询缓存表 (query_cache)

```sql
CREATE TABLE IF NOT EXISTS query_cache (
    id TEXT PRIMARY KEY DEFAULT (lower(hex(randomblob(16)))),
    
    -- 缓存键
    sql_hash TEXT NOT NULL UNIQUE,
    sql TEXT NOT NULL,
    
    -- 缓存数据
    result_json TEXT NOT NULL,
    columns_json TEXT NOT NULL,
    
    -- 统计
    row_count INTEGER,
    execution_time_ms INTEGER,
    
    -- 有效期
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    expires_at DATETIME,
    
    -- 索引
    INDEX idx_sql_hash (sql_hash),
    INDEX idx_expires_at (expires_at)
);
```

**说明：**
- 缓存查询结果，避免重复计算
- 使用 SQL 哈希作为键
- 支持过期时间

#### 2.2.4 仪表盘表 (dashboards)

```sql
CREATE TABLE IF NOT EXISTS dashboards (
    id TEXT PRIMARY KEY DEFAULT (lower(hex(randomblob(16)))),
    
    -- 基本信息
    name TEXT NOT NULL,
    description TEXT,
    
    -- 布局和组件配置
    layout_json TEXT NOT NULL, -- JSON 格式
    widgets_json TEXT NOT NULL, -- JSON 格式
    
    -- 元数据
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    is_favorite BOOLEAN DEFAULT FALSE,
    
    -- 索引
    INDEX idx_is_favorite (is_favorite),
    INDEX idx_created_at (created_at)
);
```

**说明：**
- 存储所有仪表盘配置
- 包含布局和组件信息（JSON）
- 支持收藏功能

#### 2.2.6 自动化任务表 (automation_tasks)

```sql
CREATE TABLE IF NOT EXISTS automation_tasks (
    id TEXT PRIMARY KEY DEFAULT (lower(hex(randomblob(16)))),
    
    -- 任务基本信息
    name TEXT NOT NULL,
    description TEXT,
    is_enabled BOOLEAN DEFAULT TRUE,
    
    -- 任务类型和触发器
    task_type TEXT NOT NULL, -- 'scheduled' | 'file_watch' | 'manual'
    trigger_config TEXT NOT NULL, -- JSON: cron表达式 | 监听目录等
    
    -- 任务执行配置
    steps_json TEXT NOT NULL, -- JSON数组: 任务步骤配置
    
    -- 通知配置
    notification_config TEXT, -- JSON: 任务完成通知方式
    
    -- 执行历史
    last_run_at DATETIME,
    last_run_status TEXT, -- 'success' | 'failed' | 'skipped'
    last_run_error TEXT,
    next_run_at DATETIME,
    
    -- 统计信息
    total_runs INTEGER DEFAULT 0,
    success_runs INTEGER DEFAULT 0,
    failed_runs INTEGER DEFAULT 0,
    avg_execution_time_ms INTEGER,
    
    -- 元数据
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    created_by TEXT,
    
    -- 索引
    INDEX idx_automation_tasks_is_enabled (is_enabled),
    INDEX idx_automation_tasks_task_type (task_type),
    INDEX idx_automation_tasks_next_run_at (next_run_at),
    INDEX idx_automation_tasks_last_run_at (last_run_at)
);
```

**说明：**
- 存储自动化任务配置
- 支持多种触发器类型（定时、文件监控、手动）
- 任务步骤以 JSON 格式存储，支持多步骤工作流
- 记录执行历史和统计信息

#### 2.2.7 任务执行历史表 (task_execution_history)

```sql
CREATE TABLE IF NOT EXISTS task_execution_history (
    id TEXT PRIMARY KEY DEFAULT (lower(hex(randomblob(16)))),
    
    -- 任务关联
    task_id TEXT NOT NULL,
    task_name TEXT NOT NULL,
    
    -- 执行信息
    started_at DATETIME NOT NULL,
    completed_at DATETIME,
    execution_time_ms INTEGER,
    
    -- 执行状态
    status TEXT NOT NULL, -- 'pending' | 'running' | 'success' | 'failed' | 'skipped' | 'cancelled'
    error_message TEXT,
    error_stack TEXT,
    
    -- 输出产物
    output_files TEXT, -- JSON数组: 生成的文件路径
    output_charts TEXT, -- JSON数组: 生成的图表信息
    
    -- 执行环境
    trigger_type TEXT, -- 'schedule' | 'manual' | 'file_watch'
    triggered_by TEXT,
    
    -- 性能指标
    peak_memory_used_bytes INTEGER,
    disk_io_bytes_read INTEGER,
    disk_io_bytes_written INTEGER,
    
    -- 索引
    INDEX idx_task_execution_history_task_id (task_id),
    INDEX idx_task_execution_history_started_at (started_at),
    INDEX idx_task_execution_history_status (status),
    FOREIGN KEY (task_id) REFERENCES automation_tasks (id) ON DELETE CASCADE
);
```

**说明：**
- 详细记录每次任务执行的完整信息
- 包括输出产物、性能指标、错误信息等
- 支持任务审计和问题排查

### 2.3 完整数据库初始化 SQL

```sql
-- 初始化脚本
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;
PRAGMA busy_timeout = 5000;

-- 1. 查询历史表
CREATE TABLE IF NOT EXISTS query_history (
```

### 3.2 VIEW 同步代码示例

```rust
pub fn sync_views(
    duckdb_conn: &duckdb::Connection,
    sqlite_path: &Path,
) -> Result<(), AppError> {
    // 1. 获取 SQLite 中的所有用户表
    let sqlite_conn = rusqlite::Connection::open(sqlite_path)?;
    let mut stmt = sqlite_conn.prepare(
        "SELECT name FROM sqlite_master 
         WHERE type='table' 
         AND name NOT IN (
             'query_history', 'tables', 'query_cache', 
             'dashboards', 'settings', 'migrations',
             'sqlite_sequence'
         )"
    )?;
    
    let table_names: Vec<String> = stmt.query_map([], |row| row.get(0))?
        .collect::<Result<_, _>>()?;
    
    // 2. 为每个表创建或更新 VIEW
    for table_name in &table_names {
        duckdb_conn.execute(
            &format!(
                "CREATE OR REPLACE VIEW {} AS SELECT * FROM sqlite_db.{}",
                table_name, table_name
            ),
            [],
        )?;
    }
    
    Ok(())
}
```

### 4.1 迁移版本控制

```rust
pub struct Migration {
    version: i32,
    name: String,
    up_sql: String,
    down_sql: Option<String>,
}

// 迁移注册表
const MIGRATIONS: &[Migration] = &[
    Migration {
        version: 1,
        name: "initial_schema".into(),
        up_sql: include_str!("../migrations/001_initial_schema.sql"),
        down_sql: None,
    },
    Migration {
        version: 2,
        name: "add_tags_to_history".into(),
        up_sql: include_str!("../migrations/002_add_tags.sql"),
        down_sql: Some(include_str!("../migrations/002_add_tags_down.sql")),
    },
    // ... 后续迁移
];

pub fn run_migrations(conn: &rusqlite::Connection) -> Result<(), AppError> {
    // 1. 获取当前版本
    let current_version: i32 = conn.query_row(
        "SELECT COALESCE(MAX(version), 0) FROM migrations",
        [],
        |row| row.get(0),
    )?;
    
    // 2. 执行待应用的迁移
    for migration in MIGRATIONS {
        if migration.version > current_version {
            // 执行 up
            conn.execute_batch(&migration.up_sql)?;
            
            // 记录迁移
            conn.execute(
                "INSERT INTO migrations (version, name, up_sql, down_sql) 
                 VALUES (?, ?, ?, ?)",
                (
                    migration.version,
                    &migration.name,
                    &migration.up_sql,
                    &migration.down_sql,
                ),
            )?;
        }
    }
    
    Ok(())
}
```

### 6.1 混合策略设计

根据表大小自动选择回收站策略：

| 表规模 | 策略 | 说明 |

| **小表** (≤ 100,000 行) | 数据库重命名 | 快速，直接在数据库内操作 |
