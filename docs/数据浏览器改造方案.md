### 1.3 架构约束（改造中不得违反）

基于 `AGENTS.md` 和 `docs/架构现状.md`，本次改造必须遵守：

1. **分层严格**：前端组件不直接 `invoke()`，统一走 `tauriService`
2. **目录约束**：新增文件放入现有目录（`src/components/common/`、`src/services/`、`src/types/`）
3. **类型安全**：所有前后端数据结构在 `types/` 中声明，禁止 `any`
4. **接口文档前置**：新增后端命令必须先写 OpenAPI 片段再编码
5. **组件职责**：DatabaseExplorer 只负责渲染+交互，业务逻辑放 `store/` 或 `services/`
6. **禁止删除现有功能**：分组、搜索、双击生成查询、系统表保护等功能必须保留

### 🟥 P0（✅ 已全部实施）

#### F0.1 表列表接口升级 — 返回 `row_count` 和 `column_count`

**状态**：✅ 已实施

**实际实现**：
- `tauriService.listTables()` 返回 `TableInfo[]`
- `TableInfo` 字段：`name` / `row_count` / `column_count` / `is_system_table`
- 后端 `DatabaseService::list_tables_with_meta()` 对每张表执行 `SELECT COUNT(*)` 和 `PRAGMA table_info` 获取精确值
- 失败时降级为 0，不中断整体列表

**类型定义（已落地）**：
```typescript
// src/types/index.ts
export interface TableInfo {
  name: string;
  row_count: number;         // 后端精确查询
  column_count: number;      // 后端精确查询
  is_system_table: boolean;  // 后端 SqlIdentifier::is_system_table 判定
}
```

#### F0.2 表列信息接口 — 支持展开查看列详情

**状态**：✅ 已实施

**实际实现**：
- `tauriService.getTableColumns(tableName)` → 调用后端 `get_table_columns` 命令
- 后端 `DatabaseService::get_columns()` 执行 `PRAGMA table_info("table_name")`
- 前端首次点击展开时懒加载，缓存进 `columnsCache` state，5 分钟内不重复请求
- 列详情展示：列名 + 🔑主键 + 数据类型 + NOT NULL 标签 + DEFAULT 值

**类型定义（已落地）**：
```typescript
export interface ColumnInfo {
  name: string;
  data_type: string;
  nullable: boolean;
  default_value: string | null;
  is_primary_key: boolean;
  position: number;
}
```

## 五、风险点与应对策略

| # | 风险 | 严重度 | 触发条件 | 应对策略 |
|---|------|--------|----------|----------|
| **R1** | `rowCount` 查询慢 | 🔴 高 | 表数量 > 20 且含百万行大表 | ① 懒加载（显示骨架 `(...)`，后台异步查）；② 使用 `sqlite_stat1` 估算值；③ 100 行以下精确查，以上用估算 |
| **R2** | 列信息频繁请求 | 🟡 中 | 用户频繁展开/收起表 | 前端 5 分钟内存缓存；相同表名 5 分钟内不再请求后端 |
| **R3** | 右键菜单与折叠展开冲突 | 🟡 中 | 右键点击后，浏览器默认 `contextmenu` 行为干扰 | `e.preventDefault()` + 显式控制箭头区域 vs 整行区域的右键差异 |
| **R4** | 新增 `isSystemTable` 后端判断后，前后端判定不一致 | 🟡 中 | 前端保留旧判断，后端新加规则 | **以后端返回为准**：前端 `isSystemTable()` 函数废弃，改用 `table.isSystemTable` 字段 |
| **R5** | `TableInfo` 字段新增后，其他调用 `listTables()` 的组件编译报错 | 🟡 中 | Toolbar / QueryHistory / 其他地方若有调用 | 全局搜索 `listTables` 调用点，逐一更新类型消费；TS 编译检查作为 CI 门禁 |
| **R6** | 大量表导致 UI 卡顿 | 🟢 低 | 表数量 > 200 | 虚拟滚动（`react-window`）或分页；当前先做懒加载，观察实际数据规模再决策 |
| **R7** | SQLite `PRAGMA table_info` 对 DuckDB VIEW 不适用 | 🟡 中 | 用户创建了 DuckDB VIEW（如 `__trash_metadata` 的视图） | DuckDB 用 `DESCRIBE "table"` 替代 `PRAGMA table_info`；路由层根据表类型选择查询方式 |
| **R8** | 复制表名需权限 | 🟢 低 | 浏览器/桌面应用 clipboard API 权限 | Tauri 环境下使用 `window.__TAURI__?.clipboard` 或 `navigator.clipboard.writeText`，失败时静默降级（无报错） |
