## 三、关键架构决策与设计要点（v8.0 新增章节）

### 3.1 规则分层架构（v8.0 新增）

**设计原理**：Agent 协作场景下，若没有强制约束，会出现：(1) 跨界修改（如直接写 SQL 到前端）；(2) 风格不一致（snake_case 与 camelCase 混用）；(3) 安全漏洞（敏感字符串硬编码）。通过分层规则文件 + 优先级覆盖机制，将"团队约定"固化为可执行约束。

**规则优先级（高 → 低）**：

```
1. CLAUDE.local.md    ── 本地私有 override，不提交 Git（优先级最高）
2. security.md         ── 安全零容忍（SQL 注入 / 敏感数据 / 路径穿越）
3. architecture.md     ── 分层架构 + 目录门禁 + 系统表命名
4. coding.md           ── 命名规范 + 异常处理 + 设计模式
5. test.md             ── 编译门禁 + Service 层 mod tests
6. file-lock.md        ── 核心文件串行修改（解决多任务冲突）
```

**生效机制**：Agent 在处理任务前先读取 `.trae/rules/` 全目录；若本地存在 `CLAUDE.local.md`，其中的规则覆盖通用规则；每次通过 `general_purpose_task` 发起子任务时，必须在 prompt 开头按 8 行模板声明角色与约束。

### 3.2 多角色 SubAgent 调度（v8.0 新增）

**5 个固定角色 + 目录门禁**：

| 角色 | 允许目录 | 禁止目录 | 交付物 |
|------|---------|---------|--------|
| **架构 Agent** | `.trae/specs/`、`docs/`、`.trae/rules/`（需用户确认） | `src/`、`src-tauri/src/` | SPEC 文档、任务拆分、边界图 |
| **后端 Agent** | `src-tauri/src/commands/`、`services/`、`models/`、`database/`、`utils/` | `src/`、`tauri.conf.json`、`capabilities/default.json`、`Cargo.toml` | Rust 代码、参数化查询、`cargo check` 验证 |
| **前端 Agent** | `src/components/`、`src/store/`、`src/services/`、`src/types/`、`src/utils/`、`src/styles/`、`src/App.tsx` | `src-tauri/` | TS/TSX 代码、Store、`tsc --noEmit` 验证 |
| **重构 Agent** | 同后端/前端角色，但仅限既有文件修改 | 禁止新增文件命名；禁止变更系统表清单；禁止删除现有功能 | 代码改动 + 性能度量前后对比 |
| **文档 Agent** | `docs/`、`README.md`、`.trae/specs/` | 禁止修改任何代码文件 | Markdown 文档、任务记录 |

**调度模板（每次子任务必须包含）**：

```
【角色】@后端 / @前端 / @架构 / @重构 / @文档
【任务简述】<1 句话>
【允许目录】<明确列出>
【禁止目录】<明确列出>
【必须遵守的规则】<引用 .trae/rules/*.md 的具体章节>
【交付物】<代码/SPEC/文档>
【编译验证】<cargo check / tsc --noEmit>
【文件锁声明】<本任务会改哪些 Tier-1 文件，如无则写"无">
```

**设计权衡**：当前 TRAE 环境仅提供 `general_purpose_task` + `search` 两个 subagent 工具，无法绑定独立模型/工具。因此角色通过"prompt 模板 + 目录门禁"软约束实现。若未来环境支持工具绑定，可升级为硬约束。

### 3.3 Tier-1 文件锁机制（v8.0 新增）

**11 个核心高冲突文件（每次最多一个子任务修改）**：

| 文件 | 影响范围 |
|------|---------|

### 3.4 数据库连接管理（保留自 v6.0）

- **`DatabaseManager`**：drivers / active_connection / active_driver_name / active_db_path
- **`get_connection()`**：获取全局连接锁（Mutex Guard）
- **`lock_active_connection()`**：`match` + `PoisonError::into_inner()` 恢复策略
- **`close_connection()` / `connect()`**：切换项目前先释放再连接，避免死锁

### 3.5 系统表集中初始化（保留自 v6.0）

- **之前**：每个 command 函数都调用 `ensure_*_table_exists`，重复执行
- **现在**：统一在 `TauriAppState::new()` + `switch_project` + `open_database_from_path` 中初始化

### 3.6 参数化查询唯一合法路径（v6.3 + security.md 固化）

| 场景 | 写法 |
|------|------|
| **固定列 + 固定表** | `conn.query("SELECT id FROM tasks WHERE state = ? LIMIT ?;", &[&state, &limit])` |
| **动态 WHERE** | `Vec<String>` 拼接列名片段 + `Vec<Box<dyn ToSql>>` 收集参数；用户值不进入 SQL 文本 |
| **动态表名 / 列名** | `SqlIdentifier::new(user_input)?` 校验 → `quoted = safe_table.quote_identifier()` → 拼接安全标识符 |
| **LIKE 通配符** | `kw = format!("%{}%", keyword)` → `conn.query("WHERE name LIKE ?;", params![&kw])` |

**零容忍**：`src-tauri/src/` 内禁止出现 `format!("SELECT/INSERT/UPDATE/DELETE/ALTER/CREATE ...)` 包含用户输入的 SQL 文本拼接。

### 3.7 自动化任务执行策略（保留自 v6.0 + v6.3 加固）

- **无事务**：dispatch 失败时，run 记录和 task 状态仍需写回（避免下次调度不触发）
- **锁释放**：扫描得到候选任务 ID 后立即 `drop(conn)`；每个任务单独获取连接 → 执行 → 释放 → sleep
- **错误映射**：`simplify_sql_error()` 将底层 SQLite/DuckDB 错误映射为中文描述
- **运行日志**：每次执行产生一条 `__automation_runs` 记录，包含 start/finish/duration/output
