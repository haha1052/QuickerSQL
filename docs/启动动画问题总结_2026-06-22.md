## 一、问题总览

当前应用的启动动画在真实用户设备上存在两类核心问题：

| 问题 | 现象描述 | 发生阶段 | 用户感知 |
|------|---------|---------|---------|
| **P1 — 白屏闪烁** | 启动瞬间或启动过渡过程中出现短暂的白色矩形画面 | 0-500ms 窗口创建阶段 / 1-2s 过渡阶段 | ❌ 破坏"从桌面浮出圆形卡片"的高级感，视觉体验割裂 |
| **P2 — 矩形窗口无法透明** | 圆形 splash 卡片周围应透明显示桌面的区域实际是白色/灰色矩形边框或整个 400×400 窗口不透明 | 整个 splash 阶段 | ❌ "透明窗口 + 圆形卡片"的设计目的完全失败，呈现为普通矩形应用窗口 |

**理想视觉流程**：双击图标 → 桌面原样 → 一张圆形渐变卡片从桌面浮出（周围可看到桌面内容）→ 卡片放大后平滑扩展为完整的 1200×800 应用窗口

**实际视觉流程**：双击图标 → 白色矩形闪现 → 圆形卡片缩放到白色矩形内 → 白色矩形放大成 1200×800 的应用窗口

```
   │       └── setTimeout(80ms) → 调用 __TRIGGER_SPLASH_TRANSITION__()
   │
   ▼
```

### 2.3 Win32 边框消除（FFI 层）

**文件**：[src-tauri/src/commands/startup.rs](file:///e:/LA_DUCK/la-duck/src-tauri/src/commands/startup.rs#L24-L118)

```rust
/// ====== Windows 透明窗口边框消除 ======
///
/// 在 Windows 10/11 上，即使设置 `decorations: false, transparent: true`，
/// Win32 窗口仍可能保留一个 1px 的矩形边框（WS_EX_WINDOWEDGE 等扩展样式位）。
///
/// 解决：通过 Win32 API 清除边框样式位，并调用 DwmExtendFrameIntoClientArea(-1)
/// 让 DWM 合成器把整个窗口视为客户区（不绘制任何框架轮廓）。
///
/// 零额外 crate 依赖，纯 `extern "system"` FFI。
#[cfg(windows)]
mod win_borderless {
    use std::ffi::c_void;
    use std::ptr;

    // ==== Win32 常量（精确值，查自 winuser.h / dwmapi.h）====
    const GWL_STYLE: i32 = -16;
    const GWL_EXSTYLE: i32 = -20;
    const WS_BORDER: isize = 0x0080_0000;
    const WS_THICKFRAME: isize = 0x0004_0000;
    const WS_CAPTION: isize = 0x00C0_0000;
    const WS_EX_WINDOWEDGE: isize = 0x0000_0100;
    const WS_EX_CLIENTEDGE: isize = 0x0000_0200;
    const WS_EX_DLGMODALFRAME: isize = 0x0000_0001;
    const SWP_FRAMECHANGED: u32 = 0x0020;
    const SWP_NOMOVE: u32 = 0x0002;
    const SWP_NOSIZE: u32 = 0x0001;
    const SWP_NOZORDER: u32 = 0x0004;

    // ==== Win32 FFI 外部函数声明 ====
    extern "system" {
        fn GetWindowLongPtrW(hwnd: *mut c_void, n_index: i32) -> isize;
        fn SetWindowLongPtrW(hwnd: *mut c_void, n_index: i32, dw_new_long: isize) -> isize;
        fn SetWindowPos(
            hwnd: *mut c_void,
            hwnd_insert_after: *mut c_void,
            x: i32, y: i32, cx: i32, cy: i32,
            u_flags: u32,
        ) -> i32;
        fn GetForegroundWindow() -> *mut c_void;
        fn DwmExtendFrameIntoClientArea(hwnd: *mut c_void, p_margins: *const MARGINS) -> i32;
    }

    #[repr(C)]
    struct MARGINS {
        cx_left_width: i32,
        cx_right_width: i32,
        cy_top_height: i32,
        cy_bottom_height: i32,
    }

    /// 对给定 HWND 执行系统边框消除。如果 hwnd 是 null，退化什么都不做。
    pub unsafe fn apply(hwnd: *mut c_void) {
        if hwnd.is_null() { return; }

        // 1. 清除普通边框样式位
        let style = GetWindowLongPtrW(hwnd, GWL_STYLE);
        let new_style = style & !(WS_BORDER | WS_THICKFRAME | WS_CAPTION);
        if new_style != style {
            SetWindowLongPtrW(hwnd, GWL_STYLE, new_style);
        }

        // 2. 清除扩展边框样式位（这是"上方边缘"的主要来源）
        let ex_style = GetWindowLongPtrW(hwnd, GWL_EXSTYLE);
        let new_ex_style = ex_style & !(WS_EX_WINDOWEDGE | WS_EX_CLIENTEDGE | WS_EX_DLGMODALFRAME);
        if new_ex_style != ex_style {
            SetWindowLongPtrW(hwnd, GWL_EXSTYLE, new_ex_style);
        }

        // 3. DwmExtendFrameIntoClientArea(-1)：把整个窗口视为客户区，
        //    DWM 不再绘制任何框架轮廓。
        let margins = MARGINS {
            cx_left_width: -1,
            cx_right_width: -1,
            cy_top_height: -1,
            cy_bottom_height: -1,
        };
        let _ = DwmExtendFrameIntoClientArea(hwnd, &margins);

        // 4. 让操作系统重新应用框架更改（必需步骤）
        let _ = SetWindowPos(
            hwnd,
            ptr::null_mut(),
            0, 0, 0, 0,
            SWP_NOMOVE | SWP_NOSIZE | SWP_NOZORDER | SWP_FRAMECHANGED,
        );
    }
}
```

```rust
#[tauri::command]
pub fn window_resize_to_main(window: tauri::WebviewWindow) -> Result<ApiResponse<serde_json::Value>, String> {
    use tauri::{Size, LogicalSize};

    if let Err(e) = window.set_size(Size::Logical(LogicalSize { width: 1200.0, height: 800.0 })) {
        log::warn!("[startup] window.set_size(1200x800) 失败: {}", e);
    }

    if let Err(e) = window.center() {
        log::warn!("[startup] window.center() 失败: {}", e);
    }

    if let Err(e) = window.set_resizable(true) {
        log::warn!("[startup] window.set_resizable(true) 失败: {}", e);
    }

    // 主界面也去除边框残留（set_resizable 后某些 Windows 版本可能重新加上 WS_THICKFRAME 相关位）
    apply_borderless();

    Ok(ApiResponse {
        success: true,
        message: "resized".into(),
        data: Some(serde_json::json!({ "width": 1200, "height": 800 })),
    })
}
```

### 2.6 HTML 内联 JS：透明锁注入 + 过渡控制

**文件**：[index.html](file:///e:/LA_DUCK/la-duck/index.html#L276-L362)

```html
<script>
  window.__STARTUP_HTML_LOAD_MS__ = performance.now();
  window.__STARTUP_TIME_ORIGIN__ = performance.timeOrigin;

  // ★ 关键修复：在 JS 执行的第一时间给 html/body/#root 添加 .startup-phase 类
  // 该类使用 !important 强制 transparent 背景，防止任何第三方 CSS 覆盖透明设置。
  // 启动完成后由 AppWrapper 移除此类并设置主应用背景色。
  (function() {
    var root = document.getElementById('root');
    document.documentElement.classList.add('startup-phase');
    document.body.classList.add('startup-phase');
    if (root) root.classList.add('startup-phase');
    else {
      // #root 可能还没创建（React 还没挂载），监听 DOM 变化补上
      var observer = new MutationObserver(function() {
        var r = document.getElementById('root');
        if (r && !r.classList.contains('startup-phase')) {
          r.classList.add('startup-phase');
          observer.disconnect();
        }
      });
      observer.observe(document.body, { childList: true, subtree: false });
    }
  })();

  /**
   * 触发 splash 淡出：主应用准备好后，调用此函数
   * @param {number} transitionMs - 淡出时长，默认 200ms
   */
  window.__TRIGGER_SPLASH_TRANSITION__ = function(transitionMs) {
    var ms = Math.max(150, Math.min(350, transitionMs || 200));
    var el = document.getElementById('splash-screen');
    if (!el) return;

    // ★ 移除 .startup-phase 类（让 html/body/#root 恢复正常背景色控制）
    document.documentElement.classList.remove('startup-phase');
    document.body.classList.remove('startup-phase');
    var root = document.getElementById('root');
    if (root) root.classList.remove('startup-phase');

    el.style.transition = 'opacity ' + ms + 'ms ease-out, transform ' + ms + 'ms ease-out';
    el.style.opacity = '0';
    el.classList.add('splash-fade-out');
    setTimeout(function() {
      if (el.parentNode) el.parentNode.removeChild(el);
    }, ms + 50);
  };

  /**
   * 强制进入主应用（5s 超时兜底）
   * 同时确保 body 变成主应用背景色
   */
  window.__FORCE_TRANSITION__ = function() {
    window.dispatchEvent(new CustomEvent('splash-timeout'));
    document.body.style.background = '#f5f7fa';
    document.documentElement.style.background = '#f5f7fa';
    if (typeof window.__TRIGGER_SPLASH_TRANSITION__ === 'function') {
      window.__TRIGGER_SPLASH_TRANSITION__(200);
    }
    if (typeof window.__CLEAR_SPLASH_TIMER__ === 'function') {
      window.__CLEAR_SPLASH_TIMER__();
    }
  };

  /* 阶段文字 + 实时计时（每 50ms 更新） */
  var stageEl = document.getElementById('splash-stage');
  var timerEl = document.getElementById('splash-timer');
  var timeoutBtn = document.getElementById('splash-timeout-btn');
  var intervalId = setInterval(function() {
    var now = performance.now();
    if (timerEl) timerEl.textContent = '启动中 · ' + Math.round(now) + ' ms';
    // ... 阶段文字更新逻辑
  }, 50);

  window.__CLEAR_SPLASH_TIMER__ = function() {
    if (intervalId) clearInterval(intervalId);
  };
</script>
```

```css
/* ============================================================
   QuickerSQL 主题系统（浅色/深色/跟随系统）

   ⚠️ 透明背景约定（修改前必读）：
   - html / body / #root 三个元素必须保持 transparent 背景色
   - 直到启动完成、由 AppWrapper.tsx 显式设置 body.style.background 之前
   - 主应用背景色由 .app-shell 类或内联 style={{ background: 'var(--bg-primary)' }} 控制
   - html/body/#root 的 transition 必须为 none（避免 0.3s 白屏闪烁）
   - 禁止在任何 CSS 文件给 html/body/#root 设置非 transparent 背景色
   - 禁止在 body 的 transition 中包含 background-color（启动时会产生白屏）
   ============================================================ */

/* 基础样式重置 */
* {
  margin: 0;
  padding: 0;
  box-sizing: border-box;
  /* ↓↓↓ 这 3 条 transition 规则可能对非 html/body/#root 的子元素生效 ↓↓↓ */
  transition: border-color 0.3s ease,
              color 0.3s ease,
              box-shadow 0.3s ease;
}

/* html/body/#root 保持 transparent，无任何背景色过渡（禁止白屏闪烁） */
html, body, #root {
  background-color: transparent !important;
  background: transparent !important;
  transition: none !important;
  -webkit-transition: none !important;
}

body {
  font-family: -apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, 'Helvetica Neue', Arial, sans-serif;
```

```typescript
    setFinalRuntimeMs(now);

        if (document.documentElement) document.documentElement.style.background = '#f5f7fa';
        if (typeof window.__TRIGGER_SPLASH_TRANSITION__ === 'function') {

        }
```

## 三、问题一：白屏闪烁（3 个根因）

### 3.1 根因 A：WebView2 底层默认底色

| 项目 | 说明 |
|------|------|
| **现象** | 启动最初 100-400ms 显示白色矩形窗口，圆形卡片后出现 |
| **相关代码** | [lib.rs L470-479](file:///e:/LA_DUCK/la-duck/src-tauri/src/lib.rs#L470-L479) `background_color(Color(0,0,0,0))` |
| **发生概率** | 慢速设备（HDD/低性能 CPU）几乎 100%；SSD 高性能设备偶发 |
| **严重程度** | 高（破坏整个设计意图的第一印象） |

**技术分析**：

```
用户点击 → Rust 启动 → Tauri Builder.build() 触发 WebView2 初始化
                          │
                          ├── Tauri 代码：.background_color(Color(0,0,0,0))
                          │   ↳ 设置 WebView2 的 DefaultBackgroundColor 属性
                          │   ↳ 但此属性需要 WebView2 完成初始化后才生效
                          │
                          ├── WebView2 初始化过程（Microsoft Edge Runtime）：
                          │   ├── 创建 ICoreWebView2Controller
                          │   ├── 初始化 Edge 渲染引擎
                          │   ├── ← 【关键】此阶段显示默认白色背景
                          │   └── 应用 DefaultBackgroundColor 设置
                          │
                          └── 白色窗口 → 透明 → 圆形卡片显示
                                          ↑
                                          100-400ms 的白屏窗口
```

**根本原因**：`WebView2 初始化 → 透明属性生效` 存在不可控时序差。Tauri 提供的 `background_color(Color(0,0,0,0))` 确实是"正确的"设置方式——但它依赖 WebView2 完成初始化后才生效。

| 项目 | 说明 |

**根本原因**：`窗口尺寸变化 + WebView2 重绘 + DWM 合成 + HTML 背景色切换` 四者不同步。80ms 的延迟是经验值，在某些设备/场景下不够长。

## 四、问题二：矩形窗口无法透明（3 个根因）

### 4.1 根因 D：DwmExtendFrameIntoClientArea 调用时序 + HWND 退化路径

| 项目 | 说明 |
|------|------|
| **现象** | 圆形卡片周围显示为白色/灰色矩形，而非透明桌面 |
| **相关代码** | [startup.rs L75-108](file:///e:/LA_DUCK/la-duck/src-tauri/src/commands/startup.rs#L75-L108) + [lib.rs L483-497](file:///e:/LA_DUCK/la-duck/src-tauri/src/lib.rs#L483-L497) |
| **发生概率** | 高（在某些 Windows 配置下几乎 100%） |
| **严重程度** | 高（设计意图完全失败） |

**调用时序分析**：

```rust
// 在 lib.rs
let window = tauri::WebviewWindowBuilder::new(app, "main", url)
    .inner_size(400.0, 400.0)
    .transparent(true)
    // ...
    .build()?;                 // ← 调用 .build() 创建窗口
                                //    但窗口"已创建 ≠ 已完全绘制"

// 紧接着（微秒级时间差）
match window.hwnd() {
    Ok(hwnd) => {
        apply_borderless_to_hwnd(hwnd_ptr);  // ← DwmExtendFrameIntoClientArea
                                             //    如果窗口尚未完成第一帧绘制，
                                             //    Win32 可能丢弃该调用
    }
    Err(e) => {
        apply_borderless();  // ← 退化到 GetForegroundWindow()
                            //    风险：可能拿到错误的 HWND（如其他窗口）
    }
}
```

**根本原因（双路径）**：

1. **正常路径**：`.build()` 返回后立即调用 DwmExtendFrameIntoClientArea——窗口可能尚未完成第一帧绘制，Win32/DWM 可能丢弃该调用
2. **退化路径**：`window.hwnd()` 失败时使用 `GetForegroundWindow()`——在多窗口/多显示器/某些启动场景下可能拿到错误的 HWND

**影响验证**：可通过 log 观察 `[透明窗口] 获取 HWND 失败` 是否在出问题的设备上出现。

### 4.3 根因 F：CSS "透明" ≠ Win32 "窗口透明"

| 项目 | 说明 |
|------|------|
| **现象** | CSS 的 splash 卡片看起来正常（圆形 + 阴影），但卡片外的窗口区域显示为白色/灰色而非桌面内容 |
| **相关代码** | [index.html L46-56](file:///e:/LA_DUCK/la-duck/index.html#L46-L56) `#splash-screen { background: transparent }` |
| **发生概率** | 高（当 Win32 透明失败时必然出现） |
| **严重程度** | 高（容易被误判为 CSS 问题） |

**两层透明的区别**：

```
┌────────────────────────────────────────┐
│  Win32 层面的窗口透明                    │
│  ──────────────────────────────────     │
│  由 decorations(false) + transparent(true) +│
│  DwmExtendFrameIntoClientArea(-1) 决定     │
│  控制：窗口的哪些区域可以"看到桌面"         │
│  失败表现：整个 400×400 区域为白色/灰色     │
│                                        │
│  ┌──────────────────────────────────┐ │
│  │  CSS 层面的 DOM 元素透明            │ │
│  │  ────────────────────────────     │ │
│  │  由 background: transparent 决定    │ │
│  │  控制：DOM 元素"看到它的父元素背景"   │ │
│  │  当 Win32 透明失败时，父元素背景=白色 │ │
│  │  所以 CSS transparent 仅能让你看到    │ │
│  │  白色，而不是桌面                    │ │
│  │                                    │ │
│  │   [○ 圆形卡片 ○]                    │ │
│  │   ↓ 周围 20px 区域                 │ │
│  │   CSS transparent → 看到父元素       │ │
│  │   父元素是 WebView2 默认背景=白色    │ │
│  └──────────────────────────────────┘ │
└────────────────────────────────────────┘
```

**根本原因**：CSS `background: transparent` 只控制 DOM 元素层的透明度；Win32 层的"窗口透明"必须由 `transparent(true) + DwmExtendFrameIntoClientArea(-1)` 实现。两者**不是同一回事**——后者失败时 CSS transparent 只能露出 WebView2 的默认底色（白色）。
