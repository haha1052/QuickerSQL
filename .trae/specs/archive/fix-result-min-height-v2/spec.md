# 结果集最小高度设置失效修复（深度版）- Product Requirement Document

## Overview
- **Summary**: 深度修复"结果集最小高度设置没反应"的问题——根本原因是 ag-grid autoHeight 模式下表格不会填充父容器，导致即使设置了 minHeight，用户视觉上也感觉不到变化
- **Purpose**: 让用户在设置系统中修改 result_min_height / result_max_height 后，能够明显看到结果集卡片和表格区域的高度变化
- **Target Users**: 使用 SQL 查询功能的所有用户

## Goals
- 修改 result_min_height 后，少量数据的结果集**表格区域**高度有明显变化（不只是卡片底部空白变多）
- 修改 result_max_height 后，大量数据的结果集不超出最大高度，表格内部滚动
- 保持分页功能正常
- 保持表格交互功能正常（筛选、排序、复制等）
- 保持 ag-grid 的虚拟滚动性能

## Non-Goals (Out of Scope)
- 不修改设置系统的存储逻辑
- 不修改设置项的定义和默认值
- 不增加新的设置项
- 不重构 QueryResultItem 的整体结构
- 不修改 ag-grid 的版本或配置（除了 domLayout 相关）

## Background & Context

### 问题根因深度分析

**之前的修复只解决了一半问题**：
- ✅ 外层 container 的 minHeight 生效了（卡片变高了）
- ✅ flex 布局链路通了（内容区域能撑开）
- ❌ 但 ag-grid `domLayout="autoHeight"` 模式下，表格高度**完全由内容行数决定**，不会填充父容器
- ❌ 结果：表格下面多出空白区域，用户感觉"表格高度没变，设置没反应"

**用户感知 vs 实际变化**：
```
用户期望:
  ┌─────────────────────┐ ← minHeight=400
  │  header             │
  ├─────────────────────┤
  │  表头               │
  ├─────────────────────┤
  │  行1                │
  ├─────────────────────┤
  │  行2                │
  ├─────────────────────┤
  │  (空白行填充)       │  ← 期望：表格填充剩余高度
  ├─────────────────────┤
  │  分页栏             │
  └─────────────────────┘

实际现状 (autoHeight):
  ┌─────────────────────┐ ← minHeight=400
  │  header             │
  ├─────────────────────┤
  │  表头               │
  ├─────────────────────┤
  │  行1                │
  ├─────────────────────┤
  │  行2                │
  ├─────────────────────┤  ← 表格只有内容这么高
  │  (空白背景)         │  ← 下面全是空白，用户觉得没变化
  │  (空白背景)         │
  │  (空白背景)         │
  ├─────────────────────┤
  │  分页栏             │
  └─────────────────────┘
```

### ag-grid 两种模式对比

| 模式 | 高度由谁决定 | 适用场景 | 虚拟滚动 |
|------|------------|---------|---------|
| `autoHeight` | 内容行数 | 内容少、需要表格跟着内容变高 | ❌ 关闭（全量渲染） |
| `normal` | 父容器高度 | 内容多、需要固定高度 + 滚动 | ✅ 开启 |

### 核心矛盾
- 我们需要"少时填充、多时滚动"的混合行为
- 但 ag-grid 单一模式不能同时满足两种需求
- 分页模式下每页行数有限（默认 20 行），autoHeight 的性能问题不大

### 设计思路
既然 ag-grid 单一模式不能完美解决，我们采用**混合策略**：

1. **表格容器用 flex 填充**（minHeight 来自设置）
2. **ag-grid 用 domLayout="normal" + height: 100%**，让表格填充容器
3. 这样：
   - 内容少时：表格填满容器，数据区下方是空白行（ag-grid 背景），但表头和分页栏在两端，视觉上明显更高
   - 内容多时：受 maxHeight 限制，表格内部滚动

**用户感知**：整个表格区域（表头+数据区+分页栏）都在卡片内填充，改 minHeight 时表格整体高度变化明显。

## Functional Requirements

- **FR-1**: result_min_height 设置正确控制结果集卡片的最小高度
- **FR-2**: result_max_height 设置正确控制结果集卡片的最大高度
- **FR-3**: 表格区域（表头 + 数据区 + 分页栏）填充卡片的内容区域
- **FR-4**: 内容行数少时，表格区域保持最小高度，数据区有空白
- **FR-5**: 内容行数多时，表格区域不超过最大高度，内部滚动
- **FR-6**: 分页功能正常，分页栏始终可见
- **FR-7**: 支持表格/图表/执行计划三种视图切换

## Non-Functional Requirements

- **NFR-1**: 不引入明显的性能问题（分页模式下数据量有限）
- **NFR-2**: 不破坏现有的表格交互功能
- **NFR-3**: 代码改动量小，风险可控

## Constraints

- **Technical**: 必须使用 ag-grid community 版
- **兼容性**: 必须兼容现有的分页模式
- **依赖**: 依赖现有的设置系统

## Assumptions

- 用户期望的是"整个表格区域高度变化"，而不是"只有数据行变多"
- 数据区底部有空白行是可接受的（只要整体高度变化明显）
- 分页模式下每页 20 行左右，normal 模式性能没问题

## Acceptance Criteria

### AC-1: 最小高度设置视觉上生效
- **Given**: 结果集只有 2-3 行数据
- **When**: 用户将 result_min_height 从 200 改为 400
- **Then**: 整个结果卡片高度明显变高，表格区域（表头+数据区+分页栏）填充了卡片，视觉上能明显看出高度变化
- **Verification**: `human-judgment`

### AC-2: 最大高度设置生效
- **Given**: result_max_height 设置为较小值（如 300），结果集有大量数据
- **When**: 查看结果集
- **Then**: 表格区域不超过最大高度，数据区内部出现滚动条
- **Verification**: `human-judgment`

### AC-3: 分页功能正常
- **Given**: 结果集有多页数据
- **When**: 用户点击分页控件切换页码
- **Then**: 分页正常工作，分页栏始终可见
- **Verification**: `human-judgment`

### AC-4: TypeScript 编译通过
- **Given**: 代码修改完成
- **When**: 运行 npx tsc --noEmit --pretty
- **Then**: 0 errors
- **Verification**: `programmatic`

### AC-5: Rust 编译通过
- **Given**: 代码修改完成
- **When**: 运行 cargo check --quiet
- **Then**: 无 error
- **Verification**: `programmatic`

### AC-6: 表格交互正常
- **Given**: 修改后的表格
- **When**: 用户进行筛选、排序、复制、右键菜单等操作
- **Then**: 所有交互功能正常工作
- **Verification**: `human-judgment`

### AC-7: 视图切换正常
- **Given**: 有数据的结果集
- **When**: 用户在表格/图表视图之间切换
- **Then**: 视图切换正常，高度正确
- **Verification**: `human-judgment`
