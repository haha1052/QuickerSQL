# SQL编辑器布局改进 - 产品需求文档

## Overview
- **Summary**: 改进SQL编辑器的布局功能，包括调整工具栏、标签栏、执行栏的位置和高度，优化用户操作体验。
- **Purpose**: 提升用户在SQL编辑器中的使用体验，提供更合理的布局结构和更高效的操作入口。
- **Target Users**: 所有使用SQL查询功能的用户

## Goals
- 第一行：工具栏（功能栏，保持干净的符号+中文）
- 第二行左侧：SQL查询标签栏（水平滚动）
- 第二行右侧：执行栏（高度为原高度的1/3，包含新建标签按钮、查询名称、执行按钮）
- 第三行：SQL编辑器

## Non-Goals (Out of Scope)
- 不修改后端数据存储结构
- 不改变现有的SQL执行逻辑

## Background & Context
- 当前布局结构不符合用户操作习惯
- 功能栏、标签栏、执行栏位置需要重新规划
- 执行栏高度过高，浪费垂直空间

## Layout Structure (正确的布局)

```
┌─────────────────────────────────────────────────────────────────┐
│ 第一行：工具栏（功能栏，保持干净的符号+中文）                      │
├─────────────────────────────────────────────────────────────────┤
│ 第二行：SQL标签页（水平滚动）+ 新建标签（+）...          执行  │
├─────────────────────────────────────────────────────────────────┤
│ 第三行：SQL编辑器 + 结果面板                                     │
└─────────────────────────────────────────────────────────────────┘
```

## Functional Requirements
- **FR-1**: 第一行为工具栏，包含功能按钮（新建、打开、保存等），使用符号+中文标签
- **FR-2**: 第二行合并标签栏和执行栏：
  - 左侧：SQL查询标签页（水平滚动）+ 新建标签按钮（+）
  - 右侧：执行按钮
- **FR-3**: 第三行为SQL编辑器主体

## Non-Functional Requirements
- **NFR-1**: 布局调整应立即生效，无明显延迟
- **NFR-2**: 布局变化不应影响其他功能

## Constraints
- **Technical**: React + Zustand状态管理，Tauri框架

## Acceptance Criteria

### AC-1: 工具栏在第一行
- **Given**: 用户打开SQL查询页面
- **When**: 查看页面布局
- **Then**: 第一行显示工具栏，包含功能按钮（新建、打开、保存等），使用符号+中文标签
- **Verification**: `human-judgment`

### AC-2: 标签栏在第二行左侧
- **Given**: 用户打开SQL查询页面
- **When**: 创建多个查询标签页
- **Then**: 标签栏显示在第二行左侧，当标签过多时支持水平滚动
- **Verification**: `human-judgment`

### AC-3: 执行栏在第二行右侧
- **Given**: 用户打开SQL编辑器
- **When**: 查看执行栏
- **Then**: 执行栏高度为原高度的1/3，包含新建标签按钮、查询名称、执行按钮
- **Verification**: `human-judgment`

### AC-4: SQL编辑器在第三行
- **Given**: 用户打开SQL编辑器
- **When**: 查看编辑器主体
- **Then**: SQL编辑器占据第三行全部空间
- **Verification**: `human-judgment`
