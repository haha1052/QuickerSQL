### 核心发现（推翻了上一版文档的两处结论）

1. **Rust 工具链损坏（P1-1，新发现）**
   - `~/.rustup/toolchains/stable-x86_64-pc-windows-msvc/` **缺 `rustc` 二进制**，bin/ 下只有 cargo/clippy/rustfmt
   - 后果：`cargo check` / `cargo test` / `npm run tauri dev` 全部无法执行，**编译测试门禁自 2026-08-29 起形同虚设**
   - 报错：`missing manifest in toolchain 'stable-x86_64-pc-windows-msvc'`
   - 重装两次均失败：`could not rename 'component' file ... 目录不是空的。(os error 145)` —— rustup 并发 rename 与残留目录冲突
   - 修复方案：关闭占用进程 → 删 `~/.rustup/toolchains/stable-x86_64-pc-windows-msvc` + `~/.rustup/downloads` + `~/.rustup/tmp` → `rustup toolchain install stable --profile default`

2. **i18n 硬编码实为 167 处（P1-2，非 0 处）**
   - 上一版「0 处」的依据是 `scripts/scan-hardcoded.mjs`，**该脚本只匹配引号/模板字符串，漏检 JSX 裸文本**
   - 改用 `scripts/check-hardcoded-i18n.mjs`（含 JSX 文本正则）→ FAIL: 167 hits / 20 files
   - 集中在 Dashboard / Chart / Import / Automation / Workspace 模块
   - **重要口径规则：i18n 门禁必须用 `check-hardcoded-i18n.mjs`，不能用 `scan-hardcoded.mjs`**
